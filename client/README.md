# Netfly React client

Весь интерфейс работает через единое React-дерево. Старый inline-контроллер,
window.NetflyUI и window.NetflyLibrary больше не используются приложением.
HTML содержит контейнеры для React-порталов.

## Структура

- main.jsx — сборка приложения, маршрутизация и подключение страниц.
- App.jsx — общее дерево, видимость страниц, уведомления и эффекты.
- pages/ и components/ — интерфейс каталога, библиотеки, оценивания, сериалов,
  профиля, настроек и авторизации.
- state/appRuntime.js — сессия, синхронизация и действия прогресса сериалов.
- state/evaluationController.js — черновик оценки, поиск и сохранение.
- state/library.js и state/profile.js — общие хранилища с подписками React.
- api/ — запросы к серверу аккаунта, TMDB и OMDb.
- styles/components.css — компонентные стили; public/styles/app.css — общие стили.

## Запуск и проверки

- npm start — сборка и полный сервер с API. Для входа нужен этот режим.
- npm run local — только статические файлы; авторизация и API недоступны.
- npm run client:watch — пересборка клиентского кода при изменениях.
- npm run test:react — сборка и интеграционные проверки в jsdom с тестовыми API.
  Реальные аккаунты и база данных в этих тестах не используются.

Тестовый адаптер scripts/test-compatibility.js предоставляет старые имена
для существующих фикстур. Он не подключается к сайту. Доступ к тестовым
модулям включается флагом __NETFLY_TEST__ только в тестовом окружении.

esbuild создаёт public/assets/ui.js и ui.css; результаты не коммитятся.
Netlify выполняет npm run build и публикует public/. Серверные переменные
не включаются в клиентский пакет. Формат API, cookies и ключи localStorage
сохранены. Service worker кэширует клиентские ресурсы, но не запросы API.

Автоматические проверки дополнены ручной проверкой навигации, поиска,
каталога и заполнения оценки в авторизованном браузере. Ручные проверки
записи данных и мобильной вёрстки выполняются отдельно.
